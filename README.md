# تداول الافتراضي — Tadawul Virtual

منصة محاكاة لسوق أسهم سعودي خاص بأسعار افتراضية مستقلة عن السوق الحقيقي.
الرصيد افتراضي ولا يُسحب نقدًا.

## الهيكل

| المجلد | المحتوى | الحالة |
| --- | --- | --- |
| `engine/book` | دفتر الأوامر ومنطق المطابقة (Go) | جاهز ومختبَر |
| `engine/service` | ربط الدفتر بقاعدة البيانات: الحجز، التسوية، الإلغاء، اليوم التداولي | جاهز ومختبَر |
| `engine/cmd/engine` | خدمة المحرك: تقرأ الأوامر من Redis وتنشر الأحداث | جاهز |
| `engine/cmd/seed` | 10 شركات تجريبية وحسابا البوتات | جاهز |
| `engine/maker` و `engine/cmd/bot` | صانع السوق: سلّم عروض وطلبات حول سعر متحرك، سيناريوهات سعرية، ميل حسب المخزون، بوت ضجيج | جاهز ومختبَر |
| `db/schema.sql` | جداول المرحلة الأولى (PostgreSQL 16) | جاهز |
| `docker-compose.yml` | PostgreSQL و Redis للتطوير المحلي | جاهز |
| `api/` | Laravel 13 API: التسجيل، الدخول، الرصيد الابتدائي، استقبال الأوامر، بيانات السوق والمحفظة | جاهز ومختبَر |
| `engine/feed` و `engine/cmd/feed` | البث اللحظي عبر WebSocket: الأسعار، العمق، الصفقات، وتحديثات أوامر المستخدم | جاهز ومختبَر |
| `web/` | واجهة Vue 3: الشاشة المباشرة، الشارت، عمق السوق، تذكرة الأمر، المحفظة | نسخة أولى تعمل |

## محرك المطابقة

- أولوية السعر ثم الوقت.
- أوامر محددة وأوامر سوق، مع تنفيذ جزئي.
- الصفقة تُنفَّذ بسعر الأمر المنتظر في الدفتر.
- حدود التذبذب اليومية ووحدة تغيّر السعر (tick).
- منع مطابقة أمر مع أمر للمستخدم نفسه.
- الأسعار أعداد صحيحة بالهللة، بدون أي float.

```bash
cd engine
go test ./...
go test ./book -run xxx -bench .
```

## التشغيل محليًا

```bash
docker compose up -d                 # PostgreSQL و Redis، والجداول تُنشأ تلقائيًا
cd engine
go run ./cmd/seed                    # الشركات والبوتات
go run ./cmd/engine                  # المحرك
go run ./cmd/bot                     # صانع السوق (في نافذة أخرى)

cd ../api
composer install
cp .env.example .env && php artisan key:generate
php artisan serve                    # الـ API على http://127.0.0.1:8000/api/v1

cd ../engine && go run ./cmd/feed    # البث اللحظي على ws://127.0.0.1:8090/ws
cd ../web && npm install && npm run dev   # الواجهة على http://127.0.0.1:5173
```

الجداول مصدرها ملف واحد هو `db/schema.sql`. مع docker تُنشأ تلقائيًا، وبدونه: `php artisan migrate`.

السوق يعمل من 10:00 إلى 22:00 بتوقيت الرياض. للتجربة خارج الوقت:

```sql
UPDATE settings SET value = 'false' WHERE key = 'market_hours_enforced';
```

ثم أعد تشغيل المحرك.

## كيف يمر الأمر

1. الـ API (لأوامر المستخدمين) والبوتات يضيفون الأمر إلى `orders:in` في Redis. الرد على المستخدم `queued` مع مفتاح الأمر.
2. المحرك، في معاملة قاعدة بيانات واحدة: يحجز النقد أو الأسهم، يطابق، يسوّي الصفقات في الدفتر المالي والمراكز، ثم يثبّت.
3. بعد التثبيت ينشر الأحداث (`order` و `trade` و `book`) إلى `market:events`.

المحرك هو الكاتب الوحيد للأوامر والصفقات والمراكز وحركة النقد المرتبطة بالتداول.
مفتاح عدم التكرار يجعل إعادة إرسال الأمر نفسه بلا أثر.

```

```

اختبارات `service` و `api` تحتاج PostgreSQL و Redis يعملان. اختبارات `service` تمسح قاعدة البيانات المحددة، فاستخدم قاعدة مخصصة للاختبار.

## حدود معروفة

- السرعة: بين 1,500 و2,300 أمر في الثانية في تجربة محلية بعد تجميع الأوامر في معاملة واحدة. المتبقي هو عدد الاستعلامات لكل أمر، وتحسينه القادم نقل التسوية إلى دالة واحدة في قاعدة البيانات.
- خارج وقت السوق تُرفض الأوامر حاليًا (`market_closed`) بدل انتظار الافتتاح.
- أمر وقف الخسارة والعمولة غير منفذين بعد.
- البوت ينتظر إذا تأخر المحرك عن 300 أمر، لكنه ما زال يستعلم عن كل سهم في كل دورة، وهذا يحتاج تحسينًا قبل مئات الأسهم.
- الشركات العشر وأسعارها بيانات تجريبية، لا بيانات السوق الحقيقي.

## نقاط الـ API

كل الأسعار والمبالغ أعداد صحيحة بالهللة.

| الطريقة | المسار | الوصف |
| --- | --- | --- |
| POST | `/api/v1/register` | تسجيل، ويُمنح الرصيد الابتدائي |
| POST | `/api/v1/login` | دخول برقم الجوال وكلمة المرور، ويعيد التوكن |
| POST | `/api/v1/logout` | خروج |
| GET | `/api/v1/me` | المستخدم وأرصدته |
| GET | `/api/v1/market` | الشركات وآخر سعر والتغير والحدود |
| GET | `/api/v1/market/{symbol}/depth` | عمق السوق |
| GET | `/api/v1/market/{symbol}/trades` | آخر الصفقات |
| GET | `/api/v1/market/{symbol}/candles` | شموع الدقيقة |
| GET | `/api/v1/market/{symbol}/holders` | كبار الملاك |
| GET | `/api/v1/leaderboard` | قائمة الهوامير حسب صافي الثروة |
| GET | `/api/v1/news` | آخر الأخبار |
| GET | `/api/v1/portfolio` | المراكز والقيمة والربح والخسارة |
| GET | `/api/v1/orders` | أوامري (`?status=open` أو `?key=`) |
| POST | `/api/v1/orders` | أمر جديد |
| DELETE | `/api/v1/orders/{id}` | إلغاء أمر |

## لوحة الإدارة

```bash
cd api && php artisan app:make-admin 05xxxxxxxx   # ترقية مستخدم مسجَّل إلى مدير
```

يظهر للمدير زر «لوحة الإدارة» في الواجهة، وفيها:

- أوقات السوق وتطبيقها، والرصيد الابتدائي للمستخدم الجديد.
- صانع السوق لكل شركة: تشغيل وإيقاف، الفارق، عدد المستويات، الكميات، نسبة الضجيج.
- سيناريو سعري: سعر مستهدف ومدة، والبوت يمشي بالسعر إليه عبر أوامر حقيقية.
- زر إيقاف كل البوتات: يسحب كل عروضها من الدفتر.
- إيقاف واستئناف التداول على شركة.
- نشر خبر بأثر سعري (حتى ±10%) يتحول إلى سيناريو.
- مؤشر مطابقة الدفتر المالي، ويجب أن يبقى «سليمة».

المحرك يلتقط التغييرات خلال 5 ثوانٍ والبوت في دورته التالية، وكل تغيير يُسجَّل في `audit_logs`.

## البث اللحظي

اتصال WebSocket واحد على `/ws` برسائل JSON:

| القناة | المحتوى |
| --- | --- |
| `ticker` | آخر سعر لكل سهم تداول، دفعة كل 250 مللي ثانية |
| `book:<symbol>` | عمق السوق كاملًا عند كل تغيّر وعند الاشتراك |
| `trades:<symbol>` | رسالة لكل صفقة |
| `user:<id>` | تحديثات أوامر المستخدم، بعد إرسال التوكن |

```json
{"op":"auth","token":"<api token>"}
{"op":"sub","ch":["ticker","book:2222","trades:2222"]}
```

الشارت من مكتبة [Lightweight Charts](https://github.com/tradingview/lightweight-charts) من TradingView، وشعارها الظاهر في الشارت هو الإشارة التي يطلبها ترخيصها.

## الخطوة التالية

1. قائمة الشركات الكاملة، وترابط حركة أسهم القطاع الواحد.
2. الاكتتابات والتمويل بالهامش.
3. نقل التسوية إلى دالة واحدة في قاعدة البيانات لرفع السرعة.
4. انتظار الأوامر خارج وقت السوق، وأمر وقف الخسارة، والعمولة.
5. اختبارات Playwright للواجهة داخل المستودع.
